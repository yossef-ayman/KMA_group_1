## Data Model Changes
- **Project Entity**:
  - `media`: Array of `{ id, type ('image'|'video'), url, thumbnailUrl, title, sortOrder }`.
  - `coverMediaId`: ID of the designated primary cover item.
  - `status`: `'published'` | `'draft'`.
  - `isFeatured`: Boolean.
  - `location`: Mapped with legacy `tribunal`.
  - `client`: Mapped with legacy `clientType`.
  - `imageUrl` & `videoUrl`: Retained as auto-synchronized mirror properties for backward compatibility.
- **Service Entity**:
  - Populated under `data.services` and mirrored to `data.practiceAreas` on load, update, and persist.
- **Booking Entity**:
  - Status enum expanded: `new`, `contacted`, `confirmed`, `completed`, `cancelled`.

## Known Limitations
1. Media uploads currently store direct URLs, external embeds, or compressed browser data URLs. S3 / Cloudinary cloud storage has not been introduced (deferred per Phase 2–4 constraints).
2. Backend relational database migration (PostgreSQL / MySQL) is deferred to future phase.
3. Server-side session tokens / JWT RBAC are deferred to future phase; admin authentication currently relies on verified passcode sync and secure localStorage state.

---

## Current Architecture
- **Frontend**: React 18 + Vite + Tailwind CSS + Lucide React + Canvas / Framer Motion.
- **State & Data Access**: `PortfolioContext` -> `portfolioApi` (HTTP Client) with fallback to `IndexedDB` & `localStorage`.
- **Backend**: Node.js + Express.js (`api/index.js`) compatible with Vercel Serverless and standalone Node runtime.
- **Database Layer**: MongoDB / Mongoose models with embedded subdocuments for projects, services, bookings, and site config.
