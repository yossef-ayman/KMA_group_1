# KMA Development Progress — 2026-09-25

## Phase 6 — Security
- **Server-Side Authentication**: Implemented cryptographic session tokens signed with HMAC-SHA256 and stored in secure, HTTP-only, `SameSite=Lax/Strict` cookies (`kma_admin_session`).
- **Passcode Hashing**: Integrated `bcryptjs` with `ADMIN_PASSWORD_HASH` support (10 rounds) and automatic transparent migration for existing database passcodes.
- **Route Authorization (`requireAdminAuth`)**:
  - Protected mutating endpoints: `POST /api/projects`, `PUT /api/projects/:id`, `DELETE /api/projects/:id`, `POST /api/services`, `PUT /api/services/:id`, `DELETE /api/services/:id`, `POST /api/data`, `POST /api/media/upload`, `PATCH /api/bookings/:id/status`, `DELETE /api/bookings/:id`.
  - Public reads remain freely accessible: `GET /api/projects`, `GET /api/services`, `GET /api/health`, `GET /api/data`.
- **Public Booking Protection**:
  - `POST /api/bookings` remains public but is guarded by `bookingLimiter` (max 15 submissions per 15 min per IP).
  - Server-side input validation and string length sanitization enforced.
- **Rate Limiting**: Added `express-rate-limit` on `POST /api/auth/login` (max 10 attempts per 15 min).
- **CORS & Security Headers**:
  - Configurable `CORS_ORIGIN` with credentials support.
  - Security headers added (`X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, `Strict-Transport-Security` in production) without disrupting YouTube, Vimeo, or Google Drive embeds.

## Phase 7 — Media Storage
- **Dedicated Upload Endpoint**: Implemented `POST /api/media/upload` using `multer` with disk storage in `./uploads`.
- **File Validation & Safety**: Restricts uploads to validated MIME types (JPEG, PNG, WebP, GIF, MP4, WebM, QuickTime) and safe random filenames (`kma-<timestamp>-<hex>.<ext>`), preventing path traversal. File sizes capped at 10MB (images) / 50MB (video).
- **Admin UI Integration**: Updated `AdminMediaUpload.jsx` to upload directly to `/api/media/upload` and store clean URLs (`/uploads/...`) instead of multi-megabyte Base64 strings.
- **Backward Compatibility**: Existing image URLs (Unsplash, external links, legacy Base64) and external video embeds (YouTube, Vimeo, Google Drive) remain fully supported and preserved.

## Phase 9 — MySQL Database Migration (Hostinger Native)
- **Hostinger Native MySQL Architecture**: Migrated backend database layer from MongoDB/Mongoose to native MySQL 8.0 / MariaDB, eliminating third-party external dependencies (MongoDB Atlas) on Hostinger.
- **Relational Schema Design & DDL (`api/db/schema.sql`)**:
  - `portfolio`: `doc_id` VARCHAR(64) PRIMARY KEY, `data` LONGTEXT, `updated_at` DATETIME.
  - `projects`: Normalized columns (`id`, `title`, `category`, `category_label`, `client`, `location`, `year`, `date`, `value`, `description`, `outcome`, `tech_stack`, `live_url`, `github_url`, `status`, `is_featured`, `cover_media_id`, `image_url`, `video_url`, timestamps).
  - `project_media`: Normalized child table with `project_id` foreign key (`ON DELETE CASCADE`), `id`, `type`, `url`, `thumbnail_url`, `title`, `sort_order`, `created_at`.
  - `services`: `id` VARCHAR(64) PRIMARY KEY, `title`, `category`, `description`, `items` (JSON), `price`, timestamps.
  - `bookings`: `id` VARCHAR(64) PRIMARY KEY, `name`, `phone`, `email`, `event_type`, `event_date`, `location`, `message`, `status`, timestamps.
  - `settings`: `key_name` VARCHAR(64) PRIMARY KEY, `value` TEXT, `updated_at` DATETIME.
- **Database Access Layer (`api/db/mysql.js`)**:
  - Connection pooling with `mysql2/promise` supporting `MYSQL_URL` / `DATABASE_URL` or discrete parameters (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`).
  - Automatic table creation (`CREATE TABLE IF NOT EXISTS`) on connection.
  - Dedicated repository modules: `portfolioRepo`, `projectRepo`, `serviceRepo`, `bookingRepo`, `settingRepo`.
  - Non-blocking offline fallback: if MySQL is offline or unconfigured, server continues running safely using local JSON and memory cache.
- **Migration & Verification Script (`scripts/migrate_mongo_to_mysql.js`)**:
  - Automated script invoked via `npm run migrate:mysql`.
  - Extracts existing data from MongoDB Atlas (if URI provided) or local backups (`saved_portfolio.json`, `saved_bookings.json`).
  - Automatically loads and verifies all entities, auto-initializes MySQL tables, and batch-populates records.
  - Outputs a verification table comparing Source Count vs MySQL Count.
- **Backend Route Integration (`api/index.js`)**:
  - Integrated MySQL repositories into all endpoints (`/api/data`, `/api/projects`, `/api/services`, `/api/bookings`, `/api/auth/*`).
  - Updated `/api/health` to report database statuses (`{ status: "online", mode: "mysql", database: { mysql: true, mongodb: false } }`).
  - Preserved dual-mode fallback: MongoDB Atlas (if configured) or file-memory fallback.
  - Zero changes to API request/response JSON contracts or status codes.
- **Frontend & UI Preservation**:
  - 100% preservation of frontend UI/UX, React components, Vite build pipeline, and routing.
  - `npm run build` succeeds cleanly in ~5s with zero errors or warnings.

## Production Configuration
- Node version: v20.x or v22.x LTS
- Server port: Configured via `PORT` (defaults to 5000)
- Database: Hostinger MySQL (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`)
- Fallback Database: MongoDB Atlas (`MONGODB_URI` - optional)
- Session Secret: 32+ byte secret (`SESSION_SECRET`)
- Admin Passcode: Bcrypt hash (`ADMIN_PASSWORD_HASH`)
- CORS: Single domain (`CORS_ORIGIN=https://kmawedding.com`)

---

## Rollback Information
- If any deployment issue occurs on the server, execute:
  ```bash
  npm run rollback
  pm2 restart kma-production
  ```
- If switching back to MongoDB is desired at any point, unset `DB_HOST` and provide `MONGODB_URI` in `.env`.
